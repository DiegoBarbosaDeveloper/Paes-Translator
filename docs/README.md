# Paes Translator

Aplicación web de traducción multilingüe basada en Flask, SQLAlchemy, PostgreSQL y un modelo generativo opcional.

## Modelo de datos

El esquema oficial de PostgreSQL está en `db/schema.postgres.sql` y se declara con SQLAlchemy en `entities/models.py`:

- `languages` contiene el catálogo de idiomas (`es`, `piapoco`, `achagua`).
- `dataset` separa los corpus por idioma: `1 = piapoco`, `2 = achagua`.
- `translation_direction` registra las direcciones permitidas.
- `language_pair` contiene los pares de texto, su idioma origen/destino, su dataset y su estado de validación.
- `model_version`, `evaluation` y `human_evaluation` cubren el ciclo de evaluación y entrenamiento.

El ORM valida al iniciar que la base coincida con las tablas, columnas, tipos, nulabilidad, claves primarias y restricciones foráneas del esquema. No crea ni modifica tablas de forma destructiva.

Los identificadores usan `BIGINT GENERATED BY DEFAULT AS IDENTITY`, lo que permite conservar los IDs históricos importados y generar IDs nuevos de forma concurrente.

## Separación piapoco / achagua

La separación se garantiza en dos niveles:

1. **Idioma:** cada fila de `language_pair` debe apuntar a `es → piapoco` (`1 → 2`) o `es → achagua` (`1 → 3`). El importador rechaza cualquier otra dirección.
2. **Dataset:** los pares piapoco se guardan con `dataset_id=1` y los achagua con `dataset_id=2`. El repositorio usa el idioma destino para elegir el dataset al insertar palabras nuevas.

Además, `language_pair` tiene un índice único por `(source_language_id, target_language_id, lower(btrim(source_text)))` para evitar duplicados en la misma dirección.

## Configuración

1. Instala las dependencias con `pip install -r requirements.txt` (incluye `psycopg[binary]`).
2. Copia `.env.example` a `.env` y define:
   - `DATABASE_URL=postgresql+psycopg://usuario:clave@localhost:5432/postgres`
   - `SECRET_KEY`
3. Aplica el esquema sobre la base `postgres` existente:

   ```bash
   psql -U admin -d postgres -f db/schema.postgres.sql
   ```

   `init_db()` también crea las tablas al arrancar si la base está vacía.
4. Importa los datos históricos:

   ```bash
   python scripts/import_data.py --reset
   ```

5. Inicia la aplicación con `python app.py`.

El frontend obtiene los idiomas mediante `/api/languages`; no contiene códigos ni nombres de idiomas fijos.

## Importación y exportación del corpus

`scripts/import_data.py`:

- Lee `data/language_pair.csv`, `data/piapoco.csv` y `data/achagua.csv`.
- Normaliza espacios, conserva mayúsculas y erratas originales.
- Deduplica por dirección y texto de origen. Gana el archivo específico (`piapoco.csv`/`achagua.csv`) y, en empate, el ID más reciente.
- Escribe las variantes descartadas en `data/import_conflicts.csv`.
- Es idempotente y admite `--dry-run`, `--reset`, `--url` y `--data-dir`.

Resultado esperado: **75 piapoco + 24 achagua = 99 pares**.

`scripts/export_corpus.py` exporta la base a `NLLBTest1/data/raw/language_pair.csv` para que `python -m src.build_pairs` genere:

- `NLLBTest1/data/processed/spanish_piapoco.csv` (75 filas)
- `NLLBTest1/data/processed/spanish_achagua.csv` (24 filas)

## API principal

- `GET /api/languages`
- `POST /api/translate-text` con `text`, `source_lang` y `target_lang`
- `POST /add_word` con `source_text`, `target_text`, `source_lang` y `target_lang`
- `POST /api/feedback` con la dirección seleccionada
- `POST /api/training/rebuild-dataset` reconstruye el corpus de entrenamiento y reporta los conteos por idioma

Los pares lingüísticos se consultan desde `language_pair`; los archivos multimedia se mantienen en `static/uploads`.
